# 🧭 E-Bike AI Router: Vision & Master Roadmap

> **Статус документа:** Живой инженерный манифест (Single Source of Truth)  
> **Последнее обновление:** Сентябрь 2026  
> **Цель документа:** Держать команду в фокусе, отсекать второстепенный шум и четко вести продукт от прототипа к отраслевому стандарту микромобильной логистики.

---

## 🎯 1. Миссия и North Star Metric

### Миссия
Дать курьерам и логистическим паркам микромобильности (электровелосипеды, фэтбайки) инструмент маршрутизации, который **гарантирует завершение смены без внезапной разрядки аккумулятора** и минимизирует себестоимость километра доставки.

### 🌟 North Star Metric (Главная метрика)
> **0 инцидентов разрядки батареи посреди маршрута** при сохранении минимального времени доставки.

---

## 🚫 2. Анти-цели (Чего мы НЕ делаем, чтобы не распыляться)

Чтобы продукт не превратился в неповоротливого монстра, мы осознанно **отказываемся** от:
1. **Создания собственной картографической основы:** Мы не пишем свой OpenStreetMap. Мы используем готовые слои OSM / CARTO и сервисы геоданных.
2. **Клонирования Strava / соцсетей:** Никаких лент друзей, лайков за заезды и «царей горы». Только логистика, физика, время и ватт-часы.
3. **Разработки под узкую проприетарную прошивку:** Решение должно подходить как владельцу заводского велосипеда за $500, так и курьеру на кастомном «Колхознике» с китайским аккумулятором на 60V.

## 🏗️ 3. Архитектурный манифест

```
┌─────────────────────────────────────────────────────────────┐
│                       ЕДИНЫЙ ФРОНТЕНД                       │
│      Mobile-First PWA (Full-Screen Leaflet + Tailwind)      │
│  - Работает автономно на GitHub Pages (offline/client-side) │
│  - Работает как клиент для локального/облачного FastAPI      │
└──────────────┬──────────────────────────────┬───────────────┘
               │                              │
     (Автономный режим)               (Клиент-серверный режим)
               │                              │
               ▼                              ▼
┌─────────────────────────────┐┌──────────────────────────────┐
│    Client Physics Engine    ││    FastAPI Optimization API   │
│  - Быстрый расчет Вт·ч      ││  - EVRP (мульти-доставки)    │
│  - Локальный профиль высот  ││  - Скрытие API-ключей         │
│  - LocalStorage Гараж       ││  - Телеметрия и ML-дообучение│
└─────────────────────────────┘└──────────────────────────────┘
```

* **Отказ от Streamlit в пользу нативного Web:** Основным интерфейсом становится полноэкранное веб-приложение, удобное с телефона одной рукой на ходу.
* **Dual-Mode Execution (Двухрежимность):** 
  * *Light Mode:* работает чисто в браузере (GitHub Pages) без единого сервера.
  * *Pro Mode:* подключается к FastAPI бэкенду для тяжелых вычислений порядка объезда точек (TSP/VRP) и базы данных.

## 🗺️ 4. Фазы развития продукта (Milestones)

### 📍 ФАЗА 1: Ультимативный навигатор курьера (v1.0)
*Фокус: Идеальный опыт одной смены курьера.*

- [x] Физический движок тягового усилия (Tractive Effort Model: качение, воздух, гравитация, холод Li-ion).
- [x] Двухмаршрутная оптимизация (Быстрый vs Эко-пологий).
- [x] Автономная мобильная версия на GitHub Pages.
- [x] **Мульти-точки доставки (Waypoints):**
  - Поддержка маршрутов вида: *Склад/Ресторан $\to$ Адрес 1 $\to$ Адрес 2 $\to$ Адрес 3*.
  - Динамический пересчет веса (после каждой точки термосумка становится легче на вес заказа!).
  - Цветовая синхронизация маркеров точек и участков маршрута с векторными стрелками направления.
- [x] **Кастомный гараж («Мой электробайк»):**
  - Ввод вольтажа (36V / 48V / 60V / 72V) и емкости в Ah (10 / 15 / 20 / 30 Ah).
  - Сохранение параметров байка в память устройства (`localStorage`).
- [x] **Интерактивный профиль рельефа (Elevation Profile):**
  - График высот вдоль маршрута с выделением зон максимального энергопотребления (крутые горки).
- [x] **Экспорт маршрута в GPX:**
  - Возможность в один клик скачать маршрут и открыть в OsmAnd / 2ГИС / Яндекс Навигатор.
- [x] **Умный буфер обмена и геокодер:**
  - Быстрая вставка точек из 2ГИС, Яндекс Карт, Google Maps, координат и названий улиц.
  - Пакетный импорт смены курьера.
- [x] **Автоматическая синхронизация погоды:**
  - Подтягивание температуры и ветра в реальном времени через Open-Meteo API.

### 🧠 ФАЗА 2: Умная логистика и физическая оптимизация (v2.0)
*Фокус: Алгоритмы экономят силы и батарею.*

- [x] **Энерго-ориентированный коммивояжер (Energy-Aware TSP):**
  - Обычные навигаторы минимизируют километраж. Наш алгоритм переставляет точки так, чтобы минимизировать расход энергии с учетом сброса веса посылок на каждой остановке и рельефа.
- [ ] **Поправка на дорожное покрытие и сезон:**
  - Асфальт ($C_{\text{rr}} = 0.007$) vs Гравий/плитка ($C_{\text{rr}} = 0.015$) vs Снежная каша/слякоть ($C_{\text{rr}} = 0.035$).
  - Влияние на запас хода: зимой в слякоть сопротивление качению возрастает в 3-5 раз!
- [ ] **Swap-станции и зарядки по пути:**
  - Интерактивный слой станций замены АКБ / зарядок на карте.
  - Предупреждение о критическом остатке заряда и предложение заехать на ближайшую станцию.

## 🛡️ 5. Инженерная гигиена и стандарты качества (DoD)

Каждая строчка кода в проекте подчиняется следующим правилам:
1. **Безопасность прежде всего:** Никаких секретов в Git. Все приватные ключи — только в `.env` (бэкенд) или через пользовательский ввод (фронтенд).
2. **Mobile First:** Десктоп вторичен. Если кнопка неудобна для нажатия большим пальцем правой руки на экране смартфона — она переделывается.
3. **Криптографическая подпись (GPG):** Все коммиты подписываются проверенным ключом разработчика (`git commit -S`).
4. **Zero-Bloat Frontend:** Мы не тащим 500 мегабайт `node_modules`. Веб-интерфейс должен открываться за 0.5 секунды даже при медленном 3G интернете курьера.
5. **Тестируемость физики:** Любое изменение формул в `physics.py` или `physics.js` должно проверяться крайними тестами (мороз -25°C, подъем 15%, нулевой заряд).
